1. Document structure

The canonical 9-section shape

Most product-inspired systems use numbered sections:

  1. Visual theme & atmosphere
  2. Color palette & roles
  3. Typography rules
  4. Component stylings
  5. Layout principles
  6. Depth & elevation
  7. Do's and don'ts
  8. Responsive behavior
  9. Agent prompt guide

148 of 151 files (98%) use 7+ numbered ## N. sections. Style-preset systems (neon, brutalism…) often use a shorter 7-section guardrail format instead.

3. Twelve recurring patterns

Narrative cold open (§1)

First paragraph reads like art direction — metaphor, dominant color, principle. Not a bullet list first.

Linear: 'darkness as the native medium' · Vercel: 'gallery-like emptiness'

Quick color reference at top of §9

Agent guides lead with literal hex mapped to roles (Primary CTA: #5e6ad2). Tailwind names come second.

Present in ~85–90% of dev-friendly systems with §9

Example component prompts

5–6 copy-paste strings the user can feed another agent. Imperative voice.

'Build a hero section on white background…'

Non-negotiables / iteration guide

Numbered list of 5–10 rules. Word 'never' appears ~2× per file on average; 'non-negotiable' in ~10% of agent guides.

Linear: font-feature-settings cv01 ss03 is non-negotiable

One chromatic accent

Achromatic surfaces + single brand color for primary actions. Status colors only where meaning demands.

DuBois blue for DBUI; Linear indigo; Vercel near-black CTA

Three font weights, three roles

Most dev systems declare exactly 2–3 weights mapped to body / label / display.

DBUI: 400 read + 600 semibold

Typography hierarchy table

10-row table is the norm for product systems. Display sizes get negative letter-spacing formulas.

13–16px body for dev tools

Explicit depth mechanism

State borders OR shadows as the system — forbid mixing metaphors.

Vercel: shadow-as-border; DBUI: real borders + quiet shadows

Sidebar + content two-layer layout

Platform chrome (muted) wrapping white/near-white content surface.

Matches DBUI Base shell pattern

Do / Don't paired anti-patterns

Explicit failure modes: 'don't use indigo', 'don't use emoji as icons', 'don't use left-border status cards'.

Open Design craft/anti-ai-slop.md distills universal tells

Table-heavy, prescriptive prose

Dev/analyst files average ~28 table rows vs ~18 for full corpus. Agents need lookup tables, not essays.

Mintlify, ClickHouse, HashiCorp are table-dense

Package enrichment (Open Design 2.0)

Each system now ships manifest.json + DESIGN.md + tokens.css + components.html + preview pages.

Browse tokens.css alongside prose for machine-readable values
