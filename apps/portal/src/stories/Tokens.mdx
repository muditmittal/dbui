<Section title="How it fits together">

<P>
  <C>theme.config.mjs</C> is the only file you edit. Running <C>yarn design:tokens</C> generates
  <C>tokens.css</C> (the <C>--db-*</C> custom properties), <C>type.css</C> (the type utilities) and
  <C>tokens.json</C> (what the design linter enforces). Because all three come from one source, a
  token cannot drift between what ships, what Tailwind exposes and what the linter allows.
</P>

<P>
  Colour is a two-layer system: a raw primitive palette that never ships as CSS, and the semantic
  tokens below that reference it. Product code only ever names semantics — <C>bg-surface-base</C>,
  never a hex or a primitive. The dimensional families are single-layer, with their values derived
  from the scalars.
</P>

</Section>

<Section title="Type">

<P>
  Named by what the text <em>is</em>, not how big it is. The split that matters most is
  <C>label</C> versus <C>body</C>: both 13px, but a label is single-line by definition and body
  wraps, so they take different leading. <C>label</C> at 13/16 is deliberate — its line box equals
  the 16px icon box, so text and icon align in a row without adjustment.
</P>

<Note title="Each class is the whole style" variant="info">
  A <C>type-*</C> class carries family, size, line-height, tracking, weight and case. Never pair one
  with <C>leading-</C>, <C>font-</C> or <C>uppercase</C>. Numbers in a table use
  <C>{"<TableCell numeric>"}</C>, not a type style — tabular figures are a correctness property,
  and a numeric cell also needs right alignment, which no type style can express.
</Note>

<Section title="Space">

<P>
  A 4px grid, deliberately coarse above 8px. Fewer steps is what makes spacing consistent — a scale
  with every 4px increment lets any value look defensible. The half-step at the bottom exists for
  tight insets and icon nudges.
</P>

<SpaceScale tokens={space} />

<P>
  Two inline values are em-relative rather than fixed, so gaps beside text scale with the text:
  <C>--db-space-inline-xs</C> (0.25em) and <C>--db-space-inline-sm</C> (0.5em).
</P>

</Section>

<Section title="Radius">

<P>
  Six steps. Form controls take <C>sm</C>, containers and popovers take <C>md</C>, cards take
  <C>xl</C>, and pills take <C>full</C>.
</P>

<RadiusScale tokens={radius} />

</Section>

<Section title="Size">

<P>
  Control heights and icon sizes, both scaled by <C>--db-sizing-scalar</C>. Icon <C>md</C> is 16px
  on purpose: it matches the <C>label</C> line box, which is what lets text and icon sit on the same
  rhythm in a row.
</P>

<SizeScale tokens={sizeElement} kind="element" />

<SizeScale tokens={sizeIcon} kind="icon" />

</Section>

<Section title="Border and elevation">

<P>
  Three border widths. <C>thick</C> is the focus treatment on non-filled controls.
</P>

<Note title="Elevation counts down, not up" variant="warning">
  <C>1</C> is the <em>highest</em> surface, not the lowest — it is the dialog shadow. <C>2</C> is
  menus and dropdowns, <C>3</C> is the soft shadow on toasts and raised buttons, and <C>0</C> is
  flat. Read the number as "how far from the page", where 1 is furthest.
</Note>

<P>
  Elevation encodes stacking: if two surfaces overlap, the one on top takes the lower number. A
  surface that overlaps nothing is <C>0</C> or <C>3</C>, never <C>1</C>.
</P>

<BorderScale tokens={borderWidth} />

<ElevationScale tokens={elevation} />

</Section>

<Section title="Motion">

<P>
  Two bands and exactly one easing curve for the entire system. A single curve is deliberate:
  systems that ship five easings mostly ship five things nobody can choose between. There is no slow
  band — anything approaching a second reads as the product being slow, not as polish, and this is
  tooling that sits between someone and their data.
</P>

<MotionScale tokens={duration} easing="cubic-bezier(0.24, 1, 0.4, 1)" />

<P>
  <C>--db-ease-standard</C> is <C>cubic-bezier(0.24, 1, 0.4, 1)</C> — a fast start that settles,
  which suits interface feedback where the user has already committed to the action.
</P>

</Section>

<Section title="Scalars">

<P>
  Five dials that re-tune whole families from one number. <C>--db-type-scalar</C> scales the entire
  type ramp proportionally, which is the right mechanism for a roomier reading mode — a second
  parallel ramp would inflate controls along with prose. <C>--db-density-scalar</C> does the same
  for space, and <C>--db-sizing-scalar</C> for control and icon sizes.
</P>

<ScalarList tokens={scalars} />

</Section>

<Section title="Changing a token">

<P>
  Edit <C>packages/dbui/src/tokens/theme.config.mjs</C>, run <C>yarn design:tokens</C>, then
  <C>node scripts/generate-token-data.mjs</C> to refresh this page. Verify with
  <C>node scripts/design-lint/verify-token-sync.mjs</C>, which checks that the config, the shipped
  CSS and Figma still agree. Never hand-edit <C>tokens.css</C>, <C>type.css</C> or
  <C>tokens.json</C> — they are generated.
</P>
