  Rules written for consumers necessarily fire on the primitives that implement them. <C>Button</C>{" "}

<Section title="Figma design lint">

<P>
  Nine rules that run inside a Figma file through the MCP tool, plus a token-compliance score.
</P>

<Cmd lines={[["yarn design:lint:figma --target <nodeId>"]]} />

<P>
  It catches detached instances, fills and strokes not bound to a variable, primitive-bound values
  that should be semantic, off-scale spacing, non-token fonts and type sizes, and non-token radii.
</P>

</Section>

<Section title="Token pipeline">

<P>
  <C>theme.config.mjs</C> is the only place tokens change. Everything else is generated, and editing
  a generated file is the one thing guaranteed to be overwritten.
</P>

<Cmd lines={[
  ["yarn design:tokens", "config → tokens.css + linter allowlist"],
  ["yarn design:verify-sync", "assert config, CSS and Figma agree"],
]} />

<Section title="Legacy token audit">

<P>
  Written during the token migration and kept because it demonstrates a principle worth reusing: a
  verifier that shares a list with the thing it verifies proves nothing.
</P>

<Note title="Why that matters" variant="warning">
  The first migration verifier checked only the utility names in its own map and reported a
  confident zero while 474 legacy utilities remained in the codebase. The audit derives its list
  from the tokens themselves, crossed with every Tailwind colour prefix, so it cannot agree with the
  codemod by construction.
</Note>

<Cmd lines={[["node scripts/migrations/audit-legacy-tokens.mjs"]]} />

</Section>
