<Section title="Connect">

<P>
  Already wired for this repo in <C>.cursor/mcp.json</C>. Cursor reads that file at startup, so
  reload the window after changing it.
</P>

<CodeBlock caption=".cursor/mcp.json">{`{
  "mcpServers": {
    "dbui": {
      "command": "node",
      "args": ["\${workspaceFolder}/packages/dbui-mcp/src/server.mjs"]
    }
  }
}`}</CodeBlock>

<P>
  Outside the repo, point <C>args</C> at an absolute path and set <C>DBUI_ROOT</C> to a directory
  containing <C>packages/dbui/</C> or a vendored <C>dbui/</C>.
</P>

<Note title="Two deliberate behaviours" variant="info">
  Responses use the dense renderer, because they land directly in a context window rather than in a
  terminal. And an unknown name returns <C>isError</C> with suggestions rather than an empty result,
  so the agent can recover in one turn instead of guessing again.

<Section title="Why it has no dependencies">

<P>
  The MCP SDK would be the conventional choice. DBUI is deliberately close to zero-dependency, the
  protocol surface needed here is small and stable, and the npm registry is not reliably reachable
  from the corporate network. Hand-rolling the transport removed a blocker rather than adding risk.
</P>

</Section>

<Section title="Testing it by hand">

<P>The server reads newline-delimited JSON on stdin, so it can be driven without a client.</P>

<Cmd lines={[
  ["printf '%s\\n' '{\"jsonrpc\":\"2.0\",\"id\":1,\"method\":\"tools/list\"}' \\"],
  ["  | node packages/dbui-mcp/src/server.mjs"],
]} />

<P>
  A 12-case conformance harness covers <C>initialize</C>, <C>tools/list</C>, <C>tools/call</C>,{" "}
  <C>resources/list</C>, <C>resources/read</C>, unknown-method error codes and the suggestion path.
</P>
