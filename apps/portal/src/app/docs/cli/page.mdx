<Section title="The workflow it expects">

<P>
  The order matters. Picking the frame before the content is the difference between a product and a
  padded scroll column.
</P>

<Cmd lines={[
  ["yarn dbui shell", "1. pick a frame"],
  ["yarn dbui shell B --dense", "2. read its regions and budgets"],
  ["yarn dbui search \"faceted filter\"", "3. find what the regions need"],
  ["yarn dbui component Combobox --dense", "4. read the rules before using it"],
  ["yarn dbui check src/app", "5. verify the result"],
]} />

</Section>

<Section title="What a component record contains">

<P>
  Nothing here is hand-written. Guidelines and constraints come from the component's own JSDoc;
  category, use-for, avoid-for and synonyms from <C>component-index.md</C>; prop values from the CVA
  variant axes, following the import when the variants live in a shared{" "}
  <C>lib/*-variants.ts</C>.
</P>

<CodeBlock caption="yarn dbui component Button --dense">{`Button (action) import { Button, ButtonChevron, ButtonIcon } from "dbui/components/ui/button"
USE: Any click action — primary CTAs, toolbar actions, icon buttons, menu triggers
AVOID: State that persists across clicks → use Toggle; on/off settings → Switch
G: Use to trigger all click actions, no state memory
G: Default to Outline for text, Ghost for icon buttons
C: Avoid icons for Menu button variants
C: Limit to one Primary button on a page or dialog
variant: default|outline|secondary|ghost|link|destructive|danger
size: sm|md|icon-sm|icon-md`}</CodeBlock>

</Section>

<Section title="Errors">

<P>
  Unknown names return suggestions rather than nothing, and the <C>code</C> is stable so a caller
  can branch on it without matching prose.
</P>

<CodeBlock caption="yarn dbui component Buttn --json">{`{
  "error": "No component named \\"Buttn\\"",
  "code": "ERR_UNKNOWN_COMPONENT",
  "suggestions": [{ "name": "Button", "reason": "similar name" }]
}`}</CodeBlock>

</Section>

<Section title="Where it looks for DBUI">

<P>
  <C>DBUI_ROOT</C> if set, then a <C>packages/dbui/</C> directory walking up from the CLI or the
  working directory, then a vendored <C>dbui/</C> directory — so the same binary works inside this
  repo and inside a project that installed by copying.
</P>

</Section>
