<Section title="Three commands">

<P>

<Section title="How a finding is shaped">

<P>
  Both linters emit one schema, because they judge the same properties against the same sets and
  differ only in how a value reached the surface.
</P>

<DocTable
  columns={[
    { key: "field", header: "Field", width: "w-[130px]", mono: true },
    { key: "means", header: "Means" },
  ]}
  rows={[
    { field: "surface", means: "react or figma" },
    { field: "object", means: "the join key — file:line:element in code, the node id in Figma" },
    { field: "family", means: "value, structure or a11y" },
    { field: "property", means: "color, spacing, size, radius, type-size, line-height, font" },
    { field: "verdict", means: "off-set, unnamed, unreachable, stale, conflict, incomplete, missing" },
    { field: "channel", means: "class, arbitrary, inline-style, module-literal, figma-paint, figma-binding" },
  ]}
/>

<P>
  A rule name says how a value was written; <C>property:verdict</C> says what is wrong.{" "}
  <C>no-hardcoded-hex</C>, <C>no-arbitrary-color</C>, <C>inline-hardcoded-color</C> and
  Figma&rsquo;s <C>non-token-fill</C> are four names for one thing: <C>color:off-set</C>.
</P>

<P>
  Because every finding carries an object, the report groups them and names the cause. An element
  failing three checks is usually one mistake — a control built by hand — and it reads as one row
  rather than three.
</P>

</Section>

<Section title="Figma">

<P>
  The same approved sets, read from the same <C>tokens.json</C>. It checks instances against the
  published component list, fills and strokes for binding and value, spacing, radius including mixed
  corners, size, stroke weight, font family, type size, line height and weight.
</P>

<Cmd lines={[["yarn design:lint:figma --target <nodeId>", "prints a payload to run through the Figma MCP"]]} />

<Note title="Figma is sampled, code is exhaustive" variant="warning">
  This command lints nothing on its own. It prints JavaScript for an MCP host to run inside Figma
  through <C>use_figma</C>, against one node you choose. So it cannot join <C>design:audit</C>, and
  any combined report inherits the asymmetry: every line of code is checked, and Figma is checked
  where someone looked.
</Note>

</Section>

<Note title="Why no check holds its own scale" variant="info">
  Every family, ramp step, role and deleted name comes from <C>tokens.json</C>, generated from{" "}
  <C>theme.config.mjs</C>. The allowlist used to be copied forward on each run instead, so it went
  on approving stops the families had dropped. The Figma runtime carried the same fault until
  recently: its radius allowlist was a hand-written copy that matched the system by coincidence, and
