<Section title="Core principles">

<P>
  The Databricks voice is professional, authoritative and concise, but human and approachable.
</P>

<Section title="Voice and tone scale">

<P>
  Voice is the constant personality of the product. Tone flexes with the user's context and the
  stakes involved.
</P>

    { tone: "Cautious", context: "Errors, delete confirmations, permission grants", guidance: "Firm and precise for destructive or security actions", example: "Deleting this catalog can't be undone" },

    { moment: "Tooltip", tone: "Neutral", guidance: "Adds information not already in the label. No final period", example: "Serverless compute starts in seconds" },
    { moment: "Empty state", tone: "Warm", guidance: "Title of six words or fewer, one sentence for the next step", example: "No queries yet. Create a query to start." },
    { moment: "Error message", tone: "Cautious", guidance: "State what happened, why, and what to do next", example: "Couldn't run the query. Retry in a few seconds." },
    { moment: "Destructive action", tone: "Cautious", guidance: "State the exact irreversible consequence", example: "This can't be undone." },

<Section title="Sentence casing and punctuation">

<P>
  Use sentence case for every UI string — capitalize only the first word. Never use title case for
  generic labels. Follow US English, and do not use semicolons.
</P>

<DocTable
  columns={[
    { key: "exception", header: "Exception", width: "w-[190px]" },
    { key: "casing", header: "Casing", width: "w-[140px]" },
    { key: "example", header: "Example" },
  ]}
  rows={[
    { exception: "Branded products", casing: "Title Case", example: "Unity Catalog, Delta Live Tables" },
    { exception: "Generic terms", casing: "lowercase", example: "notebook, cluster, job, lakehouse" },

    { exception: "Common acronyms", casing: "As-is", example: "SQL, API, ML" },

/>

</Section>
